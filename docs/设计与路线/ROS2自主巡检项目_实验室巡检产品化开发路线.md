# ROS2 自主巡检项目：实验室巡检产品化开发路线

> 更新：2026-11-17。起点：已完成 mission 1～9。  
> 硬件：亚博 MicroROS V2 四轮标准版。工作站：VMware Ubuntu + ROS2 Humble。

## 1. 本轮目标

**小车在实验室按指定检查点巡检；发现关注通道持续被占用时，记录位置并采集图像，在 Ubuntu 界面生成事件。操作人员可请求复查、保持停车或遥控接管。障碍清除并通过复查后，系统记录处理结果，按规则恢复未完成巡检。**

第一版先做 3 个检查点、1 个关注通道，单车、单工作站运行。路线固定检查点顺序，点间由 Nav2 规划；需要必经某段通道时增加途经点或区域约束。

后续再扩展：

- **指定物品位置检查**：到固定点拍照，检查物品或标记是否出现在规定区域。
- **设备指示灯检查**：在固定视角识别指定设备的灯色、亮灭或闪烁。

先完成通道占用闭环，再复用检查点、图像和事件模块增加这两项。

## 2. 业务流程与关键规则

```text
检查点巡检 → 观察关注通道 → 确认持续占用
                              ↓
                 停止自动巡检、取消旧导航
                              ↓
                  拍照、保存位置、生成事件
                              ↓
           确认收到 / 请求复查 / 保持停车 / 遥控
                              ↓
                  复查清空 → 人工确认恢复
                              ↓
                      继续未完成检查点
```

### 2.1 怎样判断持续占用

- 在实验室地图标出关注区域，并选一个能看清该区域的停车观察点。
- 将雷达数据按采集时间对应的 TF 转到地图坐标，判断关注区域是否被占用。测试纸箱应覆盖雷达扫描高度。
- 连续观察一段时间再形成事件，过滤短暂经过；近距离避障和停车立即生效，不等待报警确认。
- 输出 `OCCUPIED`（占用）、`CLEAR`（清空）、`UNKNOWN`（无法判断）。区域被遮挡、雷达/定位失效、观察范围不足时返回 UNKNOWN。
- 清空也要持续确认。数据中断不累计时长，不能因区域里没测到点就直接判空。
- 同一区域持续存在的问题更新同一个事件。关闭后再次占用，再创建新事件。

先录制空通道、短暂经过、持续放置、遮挡四类数据，再调整占用/清空时长、有效样本数与采样间隔。

### 2.2 事件状态与操作

事件阶段：`OPEN → RECHECKING → CLEARED_PENDING_CONFIRM → RESOLVED`。复查仍占用或无法判断时回到 OPEN；清空待确认期间再次占用或数据失效时，撤销可恢复条件。

“是否确认收到”单独记录。控制模式分为 `AUTO`（巡检）、`HOLD`（等待）、`TELEOP`（遥控）；人工暂停与故障继续独立生效。

| 操作 | 系统行为 |
|---|---|
| 确认收到 | 记录确认时间，事件继续保留 |
| 请求复查 | 停车采样，返回占用、清空或无法判断；当前位置看不清时提示调整观察位置 |
| 保持停车 / 解除保持 | 显式设置或解除人工保持；解除后仍在 HOLD，等待下一步操作 |
| 申请遥控 | 终结旧导航并确认停车，满足运行条件后切到 TELEOP |
| 结束遥控 | 停车、清除旧速度并回到 HOLD |
| 确认清除并恢复 | 重新检查清空结论及运行条件，记录处理结果，恢复未完成巡检 |

无人回应时保持 HOLD，定时提醒。首轮可用 60 秒作为提醒时间；到期不自动起步。复查也设置期限，超时返回 UNKNOWN。

第一版在原地复查。视角不足时由人工遥控调整，结束遥控、停车后再查。暂不增加自动移动取景或跳过占用通道。

### 2.3 恢复与遥控

- 恢复需要新鲜有效的清空复查、人工确认、定位/导航就绪、无其他阻断事件，且人工保持、暂停和故障均已解除。
- 保存未完成检查点；恢复后重新导航和观察，已完成点不重复计数。
- 自动与遥控速度经过同一仲裁和门禁，任一时刻只允许一个来源。申请遥控前先禁止自动派发，再取消并等待旧导航终结；超时则拒绝接管。
- 遥控松键、页面断开、输入超时和模式退出均停车并清缓存；故障与人工暂停优先于遥控。
- 核对车端速度指令超时停车。Wi-Fi 中断后，停车依靠车端保护；地面运行前先验证这一机制，并准备现场停止手段。

## 3. 复用现有工程

| 入口 | 接下来的修改 |
|---|---|
| `src/patrol_manager/include/patrol_manager/mission.hpp` | 保留队列、取消屏障、token 和巡逻恢复；增加事件等待、模式切换和复查恢复规则 |
| `src/patrol_manager/src/mission_node.cpp` | 接入观察、人工指令和执行结果，统一任务派发与运动模式 |
| `src/patrol_interfaces/` | 增加业务事件、复查与操作结果接口；原 Incident 继续用于已有导航任务 |
| `src/patrol_sim/patrol_sim/guard_logic.py`、`guard.py` | 接入自动/遥控仲裁，处理切换与失联后的速度缓存 |
| `src/patrol_sim/patrol_sim/panel.py`、`http_api.py`、`src/patrol_sim/web/index.html` | 真实地图、事件卡片、照片与操作按钮 |
| `src/patrol_bringup/launch/system.launch.py`、`src/patrol_bringup/config/` | 真机启动入口、实际地图、检查点与关注区域配置 |

当前三个具体改动点：

1. 事件处置目前按 `handling_sec` 计时完成。新业务事件需要等待指令，单独管理生命周期。
2. 轻量启动链包含仿真底盘和固定 `map → odom`。真机启动时关闭它们，使用真实定位与 TF，确保只运行一套导航。
3. `Mission::permit()` 当前依赖导航执行状态。接遥控时拆分自动许可、遥控授权与共同保护条件。

雷达/图像适配和观察算法先用 Python；C++ 继续负责调度、模式与恢复。沿用现有门禁，业务模块按需要拆包。观察节点不直接发布底盘速度，ROS 回调不阻塞等待图像或人工输入。

## 4. 开发任务

按 P00～P10 逐项推进。硬件未到时，可用注入观察先开发 P03～P06 的逻辑和界面。

### P00：保存当前版本，确定场地

- 同步 Windows 与 Ubuntu 的 mission 1～9 源码，保存能运行的配置及回归结果。
- 画出运行区域，选 3 个检查点、1 个关注通道和停车观察点。
- 整理小车、雷达、相机、里程计、TF 和速度控制接口清单。

**完成检查：** 当前系统可重新启动并完成原巡逻；场地图上能明确指出巡哪里、查哪里。

### P01：接入小车与传感器

- 按厂商教程跑通原车，登记固件、镜像、ROS 版本、话题、QoS 和相机输入方式。
- 接通雷达、里程计、图像与电量；核对车体尺寸、运动模型和传感器外参。
- 先车轮悬空验证速度命令与断流停车，再低速地面测试；排除厂商 APP、手柄等旁路控制的冲突。

**完成检查：** Ubuntu 能看到实时数据并控制停车；断开命令或网络后，车端按设置停止。

### P02：建图并完成检查点巡检

- 保存实验室地图，配置实际 footprint、速度和导航参数。
- 建立 `map → odom → base_link → sensors`，新增真机启动入口。
- 按检查点顺序导航，区分到达、观察完成与本轮完成。

**完成检查：** 走完一轮，暂停后恢复原未完成点；不可达时显示原因。

### P03：实现通道持续占用检测

- 配置关注区域，按第 2.1 节实现三种观察结果和持续判定。
- 先用录制/注入数据调参数，再接实时雷达。
- 用空通道、短暂经过、纸箱放置、移走和遮挡验证结果。

**完成检查：** 短暂经过与持续占用可区分，移走后能判空，失联或看不清时返回 UNKNOWN。

### P04：增加事件与等待状态

- 定义事件 ID、区域、阶段、确认状态、关联巡检任务及操作结果接口。
- 持续占用后停止自动派发，取消旧导航，再进入 HOLD；保留同区域事件去重。
- 实现确认收到、保持停车和超时提醒，先通过脚本操作。
- 命令绑定事件 ID 和当前状态，处理重复、迟到与过期指令；区分已接收与已执行。

**完成检查：** 事件不随停留计时结束；无人回应继续等待；旧指令不改变新事件。

### P05：拍照并保存事件

- 接入实际相机，保存现场照片、关注区域、机器人位姿、雷达片段和时间。
- 使用本地事件表（可用 SQLite）与图片目录保存记录，通过事件 ID 关联。
- 标记图片采集/接收时间和数据年龄；缺图、写盘失败和磁盘不足时显示原因。
- 重启后读取未处理事件与巡检中断位置，重新观测并等待人工操作。

**完成检查：** 事件能查到对应照片与处理记录；相机失联仍保留占用报警；重启后历史可查。

### P06：完成 Ubuntu 操作界面

- 用真实地图替换仿真墙体，处理地图分辨率、原点与朝向；显示检查点、关注区域和机器人。
- 事件卡片显示位置、持续时间、照片、数据年龄、复查结果和当前等待原因。
- 增加第 2.2 节按钮，展示处理中、成功、拒绝或超时结果；状态失联时明确提示。
- 第一版在 Ubuntu 浏览器通过 loopback 使用。

**完成检查：** 操作人员能在页面完成事件确认、保持停车和复查请求，并看到最终结果。

### P07：实现遥控接管

- 增加 AUTO/HOLD/TELEOP，按第 2.3 节实现速度仲裁与接管顺序。
- 遥控采用单会话、持续使能、限速和输入超时；切换模式时清除速度缓存。
- 取消旧导航超时、故障或人工暂停时拒绝接管并说明原因。

**完成检查：** 无导航/遥控同时控制；松键或断流后停车；退出遥控回到 HOLD。

### P08：复查、关闭并恢复巡检

- 原地有界采样，持续清空后进入待确认；重新占用或数据失效时撤销该结论。
- 人工确认恢复时重新检查运行条件；分别记录事件关闭与巡检恢复结果。
- 恢复保存的未完成检查点，保留已完成进度。

**完成检查：** 纸箱移走后完成“复查—确认—恢复”；障碍仍在、视野不足或仍有故障时继续等待。

### P09：联调与连续运行

- 执行第 5 节场景，修复问题后回归相关流程。
- 重复关键操作，逐步增加连续巡检时长，记录误报、漏报、人工介入和资源变化。
- 覆盖实际光照和网络条件，并把充电、重启纳入日常操作。

**完成检查：** 能重复完成完整闭环；遇到问题能通过事件与日志定位原因。

### P10：整理可交付版本

- 整理启动/退出、地图与参数配置、事件处理、遥控、充电和常见故障说明。
- 保存可安装版本、固件/依赖清单及地图，准备一键启动入口。
- 请另一人按说明完成巡检、处理报警、复查和恢复，补齐不顺畅的步骤。

**完成检查：** 他人能独立完成一次演示；下一轮再增加物品位置或指示灯检查。

## 5. 验证场景与开发记录

| 场景 | 预期结果 |
|---|---|
| 空通道 / 短暂经过 / 持续纸箱 | 正常巡检 / 不形成持续事件 / 形成事件并拍照等待 |
| 同一障碍持续存在 | 更新原事件，不重复刷报警 |
| 无人回应 / 仅确认收到 | 提醒或记录确认，继续等待 |
| 障碍仍在 / 遮挡 / 雷达或定位失效 | 占用或 UNKNOWN，不恢复巡检 |
| 移走障碍后复查 | 持续清空，人工确认后恢复未完成点 |
| 清空待确认时再次占用 | 撤销可恢复条件 |
| 申请遥控时旧导航未终结 | 等待，超时则拒绝接管 |
| 遥控松键、页面关闭、网络中断 | 停车、清缓存；网络中断由车端保护执行 |
| 图片陈旧、相机断流或存储失败 | 显示取证异常，保留事件 |
| 重复/迟到指令、进程重启 | 不执行旧操作；历史可查，重启后等待重新确认 |

每项任务只需记下：修改文件、运行方法、预期与实际结果、日志/图片位置、待解决问题。

持续观察五项数据：占用检出/漏报、误报次数、检测延迟、完整取证事件数、巡检完成轮数与人工介入次数。停车同时观察零速度输出和车体实际停止，按实际表现调整限速与超时。

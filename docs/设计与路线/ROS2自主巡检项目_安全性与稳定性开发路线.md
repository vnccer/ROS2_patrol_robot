> 项目适配日期：2026-11-12；根据外部开发思路与当前工作区源码整理。

## 1. 这份路线要形成什么能力

**安全性与稳定性是完成 C++ 实践训练后的项目建设目标。** 当前阶段仍按原任务 1～9 建立独立开发能力；本路线的任务 10～18是后续必做规划，任务 19 为选做，均未据本文标记为完成。本次只调整文档，不实现这些功能。

这里的安全性侧重异常输入防护、运动限制和有条件恢复；稳定性侧重有界等待、异步状态一致、数据失鲜判断、故障后的可控恢复、正常退出与可复现验证。两者共用现有任务管理器、Nav2 和门禁链，不另起一套调度系统。

在已有巡逻、报警响应、优先级调度和 Nav2 导航系统上，逐步形成四种工程能力：

1. 明确任务输入的合法范围，拒绝异常任务，并解释拒绝原因。
2. 在导航、通信和传感器异常时限制运动，保持任务与 Action 状态一致，再有条件地恢复。
3. 用监控和审计说明“系统为什么停下、哪个任务受影响、恢复条件是否满足”。
4. 用故障注入和可复现指标证明自己的修改有效。

项目定位可表述为：**具有任务防护、运动保护和故障恢复能力的 ROS2 自主巡检系统**。个人特点是“有安全意识、能独立实现并验证 ROS2 C++ 功能”。完成范围和个人贡献必须能对应到代码与运行证据。

本路线中的安全性包含异常输入防护、运行保护，以及可选的通信访问控制。仿真中的零速度输出和停车测试不代表真机功能安全认证；输入校验也不能识别所有格式合法的伪造报警。

## 5. 第一阶段：输入与配置边界

### 任务 10：增加任务目标区域策略与明确拒绝原因

**前置条件与新增边界**

进入本项前，须完成并验收原报警回调整理和撤销服务。当前已有基本字段校验、去重和队列限制；本项新增的是“允许任务区域”和拒绝原因分类，不重新实现完整 Incident Guard 节点。

**功能需求**

- 在现有输入链中增加可配置的矩形区域检查：`xmin <= x <= xmax` 且 `ymin <= y <= ymax`；闭区间语义写进测试。
- 区域来自当前地图与演示路线的人工确认，不能直接套用本文坐标。当前 `geometry.py` 的地图宽度为 8 m，外墙和内部障碍仍占空间，不能把 `[0,8] × [0,8]` 直接当成安全区域。矩形只约束目标位置，不证明可达，也不保证路径绕开禁区；原实验 `(4,2)` 墙内目标即使通过矩形校验，仍应由 Nav2/总期限处理。
- 本项先约束外部 Incident 目标；巡逻点仍来自可信启动配置。若让巡逻点共用区域策略，应作为明确的配置需求加测试，不悄悄改变原巡逻路线。
- 保留原 ID、优先级、有限数、TTL、处置时间、frame 和四元数检查；为失败原因设计稳定标识，例如 `OUT_OF_REGION`、`INVALID_FRAME`、`INVALID_POSE`、`INVALID_DURATION`。
- 拒绝发生在入队与写入去重历史之前；队列、活动任务和原接收计数语义保持正确。
- TTL 仍从本机接收时刻计时，仅约束等待队列。不要未经设计就按 `target.header.stamp` 拒绝旧时间戳，这会改变原协议。

4. 全系统试验中终止本次任务管理器进程，观察状态过期与运动许可心跳失鲜两条链；记录实际停止是由哪一层保护完成。

| 非法派发数 | 非法样本产生的实际导航 Start 次数 | 0 |
| 反馈失联检测延迟 | 从当前目标接受后或最近有效反馈时刻，到首次失联检测；分别注明起点 | 不超过配置反馈期限 + 检查周期 + 实测调度余量 |
| 超时后的检测处理延迟 | 检测时刻 −（对应起点 + 配置期限） | 非负且在预先设定的调度余量内 |
| 零指令响应时间 | 从最后一次有效输入，到首次新鲜零 `/cmd_vel` 输出；记录输入种类 | 不超过门禁期限 + 门禁周期 + 预定测量余量 |
| 仿真停止时间 | 从故障触发或最后有效指令，到连续稳定低速的仿真里程计 | 单独测量，注明起点、速度阈值及持续窗口 |
| 错误恢复次数 | 条件不足、稳定窗口未满、旧目标未知时，却恢复/派发的次数 | 0 |
| 条件满足后的恢复成功率 | 在限定时间内恢复且完成后续指定动作的轮数 / 满足全部恢复前置条件的轮数 | 固定重复试验均通过，失败/超时保留 |
| 正常任务完成率 | 截止时限前完成的唯一任务数 / 本轮已接受的有效任务数 | 单独设计无撤销/无故意过期的正常集，报告实数和时限 |
| 退出与持续运行结果 | 正常退出次数/尝试次数、退出耗时、观察时长、异常退出及各故障次数 | 明确时限内退出；按实际时长报告异常，失败与残留进程保留 |
| 审计完整率 | 字段齐全且可关联的预期关键事件数 / 用例定义要求的关键事件数 | 已定义用例中为 100%，列明预期事件集合 |
| SROS2 越权传递数（选做） | 无权限端被受保护接收端实际收到的样本数 | 0，并有授权成功对照和拒绝证据 |

分母为 0 时记为 N/A，不输出 0% 或 100%。未观察到终点的样本标记超时/缺失并保留；不能只汇总成功样本。任务完成率中，主动撤销、自然过期与故意注入失败的样本分别报告，避免混入正常集。

### 10.3 时间起点与建议门限

先测正常输入频率与虚拟机调度波动，再冻结门限。下面只有“当前基线”来自编制时源码；新参数和余量均为建议起点，不是性能结果。

| 参数/判定 | 当前基线或建议 | 使用说明 |
|---|---|---|
| 门禁 watchdog | 当前默认 0.5 s | 指令、许可、有效 odom/scan 分别按本地接收时间判断 |
| 门禁 Timer | 当前 0.05 s | 失效时持续发零；进程退出时不适用 |
| 任务管理 odom 超时 | 当前默认 1.0 s | 与门禁较短超时分工，实施前核实有效配置 |
| 总目标/取消期限 | 当前默认 90 s / 3 s | 测试可用较小值，但需记录并防止正常导航误触发 |
| `feedback_timeout_sec` | 建议从 2.0 s 试起 | 先测正常反馈间隔，包含启动等待和负载情况 |
| 新增 scan 超时 | 建议从 1.0 s 试起 | 与门禁有效数据约定一致 |
| `recovery_stable_sec` | 建议从 1.0 s 试起 | 连续满足恢复条件，失效即重新计时 |
| 观察节点 status 超时 | 建议从 2.0 s 试起 | 对照实际状态频率设置，不能与 1 Hz 摘要频率混淆 |
| 仿真静止判定 | 例如线速 < 0.01 m/s、角速 < 0.02 rad/s，持续 0.3 s | 使用里程计速度，启动测试前冻结判据 |

例如门禁 0.5 s、周期 0.05 s，预先选定测量与调度余量 0.15 s，则“最后有效输入到首个零输出”的试验预算为 0.70 s。这是**待验证预算**，不表示本项目已经达到 0.70 s，也不表示实际底盘已在这一刻静止。

所有时延尽量在同一测试进程、同一单调时钟上记录。注入命令发出时刻与最后有效数据时刻不是同一个起点，需同时保存；ROS 消息时间用于关联，不直接混入跨时钟时延计算。

## 11. 统一构建、运行与测试流程

以下命令在实际 Ubuntu 工程根目录执行，先确认目录并加载环境。不要直接在 Windows 路径执行 ROS2 命令。

### 11.1 日常 C++ 修改

```bash
source /opt/ros/humble/setup.bash
colcon build --packages-up-to patrol_manager --symlink-install \
  --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
```

新增 C++ 测试要先注册到 CMake，确认实际执行且用例数正确。修改自定义接口后重新生成并构建所有使用方；检查未运行旧终端中的旧产物。

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
python3 -m pytest tests -q
```

纯策略测试在 Ubuntu 环境按项目依赖运行。Windows 预览可以辅助检查业务，但不能替代真实 Nav2 验收。

### 11.3 原集成回归

停止旧进程后，在终端一启动轻量后端：

```bash
bash scripts/run.sh rviz:=false panel:=false
```

在另一个加载过环境的终端执行：

```bash
python3 tools/ros_acceptance.py
```

原入口已存在，原结果路径为 `test_results/ros_acceptance.json`，以原任务 9 完成后的版本为准。

任务 17 的 `tools/security_acceptance.py` 是**待开发入口**；完成实现后再按其实际参数运行，并在文档补上完整命令。本文不提供尚不存在的 CLI 参数或把它当作现成工具。

### 11.4 安全测试结束的复位检查

- 关闭本次故障开关，退出本次替身和注入进程。
- 未知旧目标未终结时停止并重启整套测试环境。
- 确认默认配置、唯一正常门禁输出、Nav2 生命周期和传感器流恢复。
- 再执行一条正常报警和原关键回归，保留清理结果。
